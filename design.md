# Purpose
Synthetic local task management: list, detail, and summary form one user-value slice backed by the local HTTP API and SQLite. The Python standard-library server binds only to `127.0.0.1`; `/` serves the bundled screen, `GET /api/tasks` returns the ordered list, `GET /api/tasks/<id>` returns one task, and exact `GET /api/summary` derives total, completed, and pending counts from the same database.

# Scenarios
Start with the two seed tasks in a new disposable database, filter them case-insensitively at `#list`, open task 1 at `#task/1`, and set its completion state through `PATCH /api/tasks/1`. Open `#summary` from either list or detail to see live total, completed, and pending counts, then return through its list link. Loading, no-match, and request-error states reflect API outcomes. Same-document navigation waits for an in-flight completion update before fetching the destination, while server reads and completed mutations are coordinated only during their SQLite work. An open summary keeps confirming its on-demand result with the API so that a snapshot overlapping an earlier document's commit is replaced after that commit; a failed confirmation hides the older counts, presents the request error, and retries until either a confirmed snapshot arrives or the route changes. Returning to the list, revisiting detail or summary, navigating browser history, or reloading after a confirmed update fetches and displays the persisted state; restarting with the same database preserves that state, and an existing table is never reseeded over user changes.

# Limits
Loopback demo with a caller-supplied disposable SQLite path only. PATCH accepts exactly `{completed: boolean}`, uses a bounded body and parameterized SQL, and rejects invalid input without changing the database. Task IDs outside SQLite's positive signed-integer range are treated as missing, and summary subpaths are not routes. Summary counts are queried on demand rather than cached; the in-process database gate covers only SQLite operations, is not a cross-process coordination mechanism, and lets an unrelated request complete while another client is still supplying a body. There is no legacy database migration, arbitrary file serving, external request, external resource, browser storage, public deployment, or production authentication/authorization.
